# 祖玛项目评分细则

> 基于 `Project/README.md` 要求与 `PROBLEM.md` 中实际测试发现的问题制定。
> 总分 100 分，各维度得分乘以权重后加总。

---

## 一、功能实现（30 分）

### 1.1 核心功能（18 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **轨道初始化** | 3 | 正确生成含多种颜色彩球的初始轨道，避免初始状态即存在三连消除（3分）；能生成但存在初始三连（2分）；完全随机无结构化初始化（1分）；未实现（0分） |
| **彩球发射与插入** | 3 | 从待发射队列取球并按玩家指定位置正确插入轨道（3分）；能插入但队列管理有误（2分）；插入位置计算错误或不支持任意位置（1分）；未实现（0分） |
| **自动消除** | 4 | 正确检测并消除 ≥3 个连续同色彩球（4分）；消除逻辑基本正确但有边界遗漏（如首尾相接处未检测）（2-3分）；消除逻辑明显错误（1分）；未实现（0分） |
| **连锁消除** | 4 | 消除后正确连接断开的两段并递归检测，支持多级连锁（4分）；只检测一级消除未递归（2分）；未实现连锁（0分） |
| **撤销操作** | 2 | 可撤销上一步插入/道具操作，正确恢复轨道与队列状态（2分）；只能部分恢复（1分）；未实现（0分） |
| **胜负判断** | 2 | 同时具有胜利条件（轨道清空）和失败条件（如回合耗尽/队列为空且轨道非空）（2分）；仅有胜利或仅有失败条件（1分）；无明确终点，游戏永不结束（0分） |

### 1.2 额外道具功能（12 分）

> 要求至少实现 **2 种**额外道具，每种 6 分。超出 2 种的按最高分的 2 种计算。

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **道具一** | 6 | 道具设计合理、利用数据结构特性实现（如炸弹=链表区间删除、跳过=队列重排）（5-6分）；道具可用但与数据结构关联弱（3-4分）；道具存在但逻辑有bug（如炸弹后未触发连锁消除检测）（1-2分）；道具无法使用（0分） |
| **道具二** | 6 | 同上 |

**道具设计参考方向：**
- 💣 炸弹：消除指定位置周围或轨道上所有同色彩球
- 🔀 重排/洗牌：调整待发射队列顺序
- ⏪ 回退：移除队尾彩球
- 🎨 变色：改变轨道上某球颜色
- 🌈 彩虹球：插入后可匹配任意颜色
- ⏭ 跳过：跳过当前回合

## 二、数据结构设计（30 分）

### 2.1 数据结构选择与合理性（18 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **轨道数据结构** | 8 | **自实现链表**（双向链表含哨兵节点，insert/remove 操作完整）（7-8分）；使用 STL `std::list` 且能说明选择理由（5-6分）；使用数组/vector 实现轨道（插入删除效率低）（2-4分）；直接使用 JS 数组而 C++ 无实质实现（0-2分） |
| **待发射队列数据结构** | 5 | **自实现队列**（链表+头尾指针，enqueue/dequeue O(1)）（5分）；使用 STL `std::queue`/`std::deque` 且能说明理由（3-4分）；未使用队列结构（1-2分） |
| **撤销栈数据结构** | 5 | **自实现栈**（支持完整状态快照的深拷贝与恢复）（5分）；使用 STL `std::stack` 且快照完整（3-4分）；快照不完整（仅保存部分状态）（1-2分）；未实现撤销/无栈结构（0分） |

### 2.2 数据结构与算法结合（12 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **插入操作** | 3 | 充分利用链表 O(1) 中间插入特性（3分）；插入需遍历定位但实现正确（2分）；插入效率低或有bug（1分） |
| **消除操作** | 3 | 利用链表区间删除特性高效移除连续同色节点（3分）；实现正确但效率一般（2分）；消除逻辑有明显性能问题（1分） |
| **连锁消除** | 3 | 消除后从连接点重新扫描，算法正确且高效（3分）；递归/循环实现正确但效率可优化（2分）；连锁逻辑有遗漏（1分） |
| **道具与结构结合** | 3 | 道具实现体现数据结构特性（如炸弹利用链表遍历+区间删除、跳过利用队列节点操作）（3分）；道具可用但未体现数据结构优势（2分）；道具实现粗糙（1分） |

## 三、用户交互（20 分）

### 3.1 界面实现（10 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **交互方式** | 5 | 图形化 Web 界面，视觉清晰可交互（5分）；Web 界面但较为简陋（3-4分）；纯命令行交互（2分）；英文界面且无中文支持（在此基础上扣1分） |
| **视觉呈现** | 5 | 彩球颜色区分清晰、轨道动画流畅、状态信息（分数/回合/队列预览）展示完整（5分）；基本可用但视觉效果一般（3-4分）；视觉效果差或信息展示不全（1-2分） |

### 3.2 用户体验（10 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **操作便捷性** | 5 | 操作直观（如点击轨道空位插入），反馈及时，错误操作有提示（5分）；能操作但不够直观（3-4分）；操作困难、反馈缺失（1-2分） |
| **游戏完整性** | 5 | 可正常完成一局游戏（从开始到胜利/失败），重开功能正常（5分）；能玩但中途可能出错（3-4分）；无法正常游玩（0-2分） |

## 四、代码质量（20 分）

### 4.1 代码组织与结构（10 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **文件模块划分** | 5 | C++ 代码按功能分文件（如 Game.hpp/cpp、数据结构头文件分离）（5分）；前后端分离但 C++ 代码全在单文件（3分）；所有代码混在一个文件无分层（如所有逻辑在 server.cpp 单一文件中）（1-2分） |
| **前后端职责分离** | 5 | 后端 C++ 负责全部游戏逻辑与数据结构，前端仅负责视图渲染与 API 调用（5分）；游戏逻辑大量放在前端 JS 中，C++ 后端沦为空壳（0-2分） |

### 4.2 注释与文档（10 分）

| 子项 | 分值 | 评分标准 |
|------|------|----------|
| **代码注释** | 5 | 关键函数、复杂算法有清晰注释，数据结构定义有说明（5分）；有注释但不充分（3-4分）；基本无注释（0-2分） |
| **实验报告/README** | 5 | README 包含设计思路、数据结构选择理由、核心函数原理说明、运行方法（5分）；文档存在但不完整（3-4分）；无文档或文档与实现不符（0-2分） |

## 五、常见扣分项（检查清单）

以下为 `PROBLEM.md` 中发现的典型问题，评分时重点检查：

| 常见问题 | 涉及维度 | 说明 |
|----------|----------|------|
| ❌ 游戏逻辑放在 JS 中，C++ 无实质实现 | 数据结构设计、代码质量 | 违背项目初衷，后端成了摆设 |
| ❌ 文件结构差，所有代码混在单一文件 | 代码质量 | `server.cpp` 包含全部逻辑，无 `.hpp`/`.cpp` 分离 |
| ❌ 无失败条件，游戏永不结束 | 功能实现 | 完全随机化彩球导致无法正常判定胜负 |
| ❌ 球的组合总数不是 3 的倍数导致无法胜利 | 功能实现 | 初始轨道 + 待发射队列的球数配置有误 |
| ❌ 道具触发后未调用连锁消除检测 | 功能实现 | 炸弹等道具消除后需检测新形成的三连 |
| ❌ 使用数组/vector 替代链表实现轨道 | 数据结构设计 | 插入删除 O(n)，未体现链表优势 |
| ❌ 英文界面无中文支持 | 用户交互 | 要求中文环境 |
| ❌ 无注释或注释极少 | 代码质量 | 代码可读性差 |
| ❌ 文档与实现不一致 | 代码质量 | 文档写了但功能实际未实现 |
| ❌ 道具不可用/无法发射彩球 | 功能实现 | 功能直接被破坏 |

| 等级 | 分数区间 | 对应测试案例 |
|------|----------|-------------|
| 🏆 优秀 | 90-100 | 数据结构自实现、代码分层清晰、功能完整、道具丰富、文档详尽 |
