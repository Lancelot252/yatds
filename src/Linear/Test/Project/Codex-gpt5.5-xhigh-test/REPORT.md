# 栈、队列和链表综合应用实验报告

## 设计思路

本项目实现一个简化版祖玛游戏。我的实现要求是：

> 在 `Project/Codex-gpt5.5-xhigh-test` 中完成项目；使用 HTML 做用户界面；后端代码使用 C++；实现轨道初始化、彩球发射、指定位置插入、自动消除、连锁消除、撤销、胜负判断，并加入道具功能。

程序采用浏览器界面加 C++ 本地服务的结构：

- 前端：`web/index.html`，负责显示轨道、发射队列、分数、道具和操作按钮。
- 后端：`src/main.cpp` 提供简单 HTTP 服务和 API。
- 游戏逻辑：`src/zuma_game.hpp`、`src/zuma_game.cpp` 封装轨道、队列、撤销历史、消除规则和胜负判断。

## 数据结构设计

1. 彩球轨道：`std::list<char>`

轨道需要频繁在任意位置插入彩球，也需要删除一段连续彩球。链表在拿到迭代器后可以高效插入和删除，符合祖玛轨道“连接、断开、再连接”的特点。

2. 待发射彩球队列：`std::queue<char>`

玩家每次只能使用队首彩球，发射后从队列弹出。换球道具会把队首彩球移到队尾，体现先进先出的队列特点。

3. 撤销历史：`std::stack<Snapshot>`

每次有效操作前保存一份游戏快照，撤销时弹出栈顶快照并恢复。最近一步优先撤销，符合栈的后进先出特性。

## 核心功能函数说明

### `insertBall(std::size_t position)`

该函数完成一次普通发射：

1. 检查游戏是否仍在进行、发射队列是否为空、插入位置是否合法。
2. 调用 `pushUndo()` 保存操作前的快照。
3. 从 `std::queue` 队首取出当前彩球。
4. 使用链表迭代器将彩球插入到指定槽位。
5. 调用 `resolveEliminations()` 执行消除和连锁消除。
6. 调用 `checkGameOver()` 判断胜负。

### `resolveEliminations()`

该函数负责自动消除和连锁消除。实现方式是反复扫描链表：

1. 从链表头部开始统计连续同色彩球数量。
2. 如果某一段长度大于等于 3，就使用 `list::erase` 删除这一整段。
3. 删除后重新从头扫描，因为左右两段连接后可能产生新的三连。
4. 直到没有可消除段为止。

这种循环扫描可以覆盖题目中的连锁消除示例。

### `undo()`

撤销功能使用栈保存快照。普通发射、爆破、同色清除、换球都会先保存快照。调用撤销时恢复栈顶快照，包括轨道、发射队列、分数、步数、道具数量和游戏状态。

### `usePowerup(type, position)`

项目包含两个额外道具：

- `bomb`：爆破目标位置及左右相邻彩球，然后继续检测连锁消除。
- `sweep`：清除轨道上与目标位置同色的所有彩球，然后继续检测连锁消除。

另有 `rotateLauncher()` 换球功能，把队首彩球移动到队尾，用队列操作改变下一发彩球。

### `checkGameOver()`

胜负条件如下：

- 轨道为空：胜利。
- 轨道长度达到上限或发射队列为空但轨道仍未清空：失败。
- 其他情况：继续游戏。

## 运行说明

进入项目目录：

```bash
cd /Users/a252/Documents/code/yatds/src/Linear/Project/Codex-gpt5.5-xhigh-test
```

编译：

```bash
make
```

运行：

```bash
make run
```

浏览器打开：

```text
http://localhost:8080
```

如果 8080 端口被占用，可以直接指定端口：

```bash
./build/zuma_server 8090
```

然后打开 `http://localhost:8090`。
