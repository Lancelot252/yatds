# 祖玛游戏实验报告

## 一、项目概述

本项目利用**双向链表**、**队列**和**栈**三种数据结构，实现了一个经典的祖玛消除游戏。游戏采用 C/S 架构：后端使用 C++ 实现核心游戏逻辑和 HTTP 服务器，前端使用 HTML/CSS/JavaScript 构建图形化用户界面。

## 二、设计思路

### 2.1 Prompt 设计

```
完成一个祖玛游戏项目，要求：
1. 使用双向链表表示彩球轨道（支持高效的中间插入和删除）
2. 使用队列（std::queue）管理待发射彩球（FIFO 语义）
3. 使用栈（std::stack）实现撤销功能（LIFO 语义）
4. 实现彩球轨道初始化、指定位置插入、自动消除、连锁消除、撤销操作、胜负判断
5. 后端 C++ 提供 HTTP RESTful API，前端 HTML 图形界面
6. 消除规则：连续 ≥3 个同色彩球自动消除，消除后连接处可能触发连锁消除
```

## 三、数据结构设计

### 3.1 双向链表 — 彩球轨道

```cpp
struct BallNode {
    char color;       // 彩球颜色（R/G/B/Y）
    BallNode* prev;   // 前驱节点
    BallNode* next;   // 后继节点
};
```

**选择原因与优点：**
- 祖玛游戏需要频繁在轨道**任意位置**插入和删除彩球
- 双向链表在已知位置插入/删除的时间复杂度为 **O(1)**
- 支持从插入点向**两侧遍历**，方便检测连续相同颜色的彩球
- 使用头尾哨兵节点（head/tail）简化边界处理

### 3.2 队列 (std::queue) — 待发射彩球

```cpp
std::queue<char> launchQueue;  // 存储待发射彩球颜色
```

**选择原因与优点：**
- 彩球按顺序发射，严格遵循**先进先出 (FIFO)** 原则
- `std::queue` 提供 O(1) 的 `push()` 和 `front()/pop()` 操作
- 语义清晰，代码可读性强

### 3.3 栈 (std::stack) — 撤销历史

```cpp
struct GameState {
    std::string track;        // 轨道彩球序列
    std::string launchQueue;  // 待发射队列
    int score;                // 当前得分
    int ballsEliminated;      // 已消除球数
};

std::stack<GameState> undoStack;  // 保存历史状态
```

**选择原因与优点：**
- 撤销操作天然遵循**后进先出 (LIFO)** 原则
- 每次操作前保存完整游戏状态快照到栈中
- 撤销时弹出栈顶状态，完整恢复轨道、队列和分数
- `std::stack` 提供 O(1) 的 `push()` 和 `pop()` 操作

## 四、核心功能函数原理

### 4.1 游戏初始化 — `initGame()`

```cpp
void initGame(const std::string& initialTrack, const std::string& initialQueue);
```

**原理：**
1. 清空现有轨道（遍历删除所有链表节点）
2. 清空队列和撤销栈
3. 遍历 `initialTrack` 字符串，为每个字符创建 `BallNode` 并追加到链表尾部
4. 遍历 `initialQueue` 字符串，将每个字符入队

**时间复杂度：** O(n + m)，n 为轨道长度，m 为队列长度

### 4.2 彩球插入 — `insertBall()`

```cpp
int insertBall(int position);
```

**原理：**
1. 调用 `saveState()` 保存当前状态到撤销栈
2. 从队列 `front()` 取出一个彩球颜色，`pop()` 出队
3. 从链表头遍历到指定位置 `position`
4. 创建新节点，在目标位置前插入（修改前后指针）
5. 调用 `eliminate()` 从新插入节点开始检测消除
6. 调用 `checkGameEnd()` 判断游戏是否结束

**时间复杂度：** O(n)，n 为轨道长度（遍历到插入位置）

### 4.3 自动消除 — `eliminate()`

```cpp
int eliminate(BallNode* pos);
```

**原理：**
1. 从插入位置 `pos` 向**左**遍历，找到连续相同颜色球的左边界
2. 从插入位置 `pos` 向**右**遍历，找到连续相同颜色球的右边界
3. 统计连续相同颜色球的数量
4. 如果数量 ≥ 3：
   - 删除区间内所有节点（释放内存）
   - 重新连接左右两侧节点
   - 更新得分（每球 10 分）和消除计数
   - **连锁消除检测**：如果连接处两侧节点颜色相同，调用 `eliminateChain()` 继续消除

**时间复杂度：** O(k)，k 为消除的球数

### 4.4 连锁消除 — `eliminateChain()`

```cpp
int eliminateChain(BallNode* left, BallNode* right);
```

**原理：**
1. 从连接处的 `left` 和 `right` 节点向两侧扩展
2. 统计连续相同颜色球的数量
3. 如果数量 ≥ 3：
   - 删除区间内所有节点
   - 重新连接
   - 连锁消除得分更高（每球 15 分）
   - **递归**检测新的连接处是否继续消除

**时间复杂度：** O(k)，k 为连锁消除的球数（递归深度取决于连锁次数）

### 4.5 撤销操作 — `undo()`

```cpp
bool undo();
```

**原理：**
1. 检查撤销栈是否为空
2. 弹出栈顶的 `GameState` 快照
3. 清空当前轨道，根据快照重建链表
4. 清空当前队列，根据快照重建队列
5. 恢复得分和消除计数
6. 重置游戏结束标志

**时间复杂度：** O(n + m)，n 为轨道长度，m 为队列长度

### 4.6 状态保存 — `saveState()`

```cpp
void saveState();
```

**原理：**
1. 遍历链表，将轨道彩球序列转为字符串
2. 复制队列内容转为字符串
3. 记录当前得分和消除数
4. 将完整状态压入撤销栈

**时间复杂度：** O(n + m)

### 4.7 胜负判断 — `checkGameEnd()`

```cpp
void checkGameEnd();
```

**原理：**
- **胜利**：轨道为空（`trackSize == 0`）且队列为空
- **失败**：队列为空但轨道还有彩球

## 五、API 接口设计

| 方法 | 端点 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/api/init` | 初始化游戏 | `{track, queue, mode}` | 游戏状态 JSON |
| POST | `/api/insert` | 插入彩球 | `{position}` | 游戏状态 JSON + eliminated |
| POST | `/api/undo` | 撤销操作 | 无 | 游戏状态 JSON |
| GET | `/api/status` | 获取状态 | 无 | 游戏状态 JSON |

### 6.4 游戏玩法

1. **开始游戏**：选择"自定义开始"（输入轨道和队列序列）或"随机开始"
2. **插入彩球**：点击轨道间的竖线（插入位置指示器），将下一个待发射彩球插入该位置
3. **消除规则**：连续 3 个或以上同色彩球自动消除，可能触发连锁消除
4. **撤销操作**：点击"撤销"按钮回退上一步
5. **胜利条件**：消除轨道上所有彩球且队列为空

## 八、总结

本项目综合运用了三种核心数据结构：
- **双向链表**实现了高效的轨道插入和删除操作
- **队列**管理了彩球的发射顺序
- **栈**支持了撤销功能的状态回滚

通过 C/S 架构分离了游戏逻辑和用户界面，后端提供 RESTful API，前端提供美观的图形化交互体验。消除算法支持连锁消除，计分系统区分普通消除和连锁消除的得分，增加了游戏趣味性。
