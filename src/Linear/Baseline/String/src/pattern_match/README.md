# 模式匹配算法 (Pattern Match)

本组任务是完成 C++ 版字符串的模式匹配。`match.hpp` 声明并导出了 `naiveMatch`（朴素匹配）、`getNext`（部分匹配表生成）和 `kmpMatch`（KMP匹配算法），`match.cpp` 标示并实现了对应的基础函数，`test_match.cpp` 提供基础的运行检查。

## 需要完成的内容（循序渐进版）

为了更好地理解模式匹配，本练习分为了三个递进的步骤。建议同学们按顺序完成：

### Step 1. 分析与测试朴素算法
- `match.cpp` 中已经给出了朴素匹配算法（`naiveMatch`）。
- **你的任务**：在 `test_match.cpp` 中构造两种极端的测试用例文本（例如主串是由大量重复字符构成的很长的字符串，但在末尾才与模式串产生失配）。并测试在这样糟糕的用例下，朴素算法的耗时表现。

### Step 2. 实现基础的 KMP 算法
- `match.cpp` 中已经给出了用于求模式串 `next` 数组的函数 `getNext`。观察并理解它是如何消除主串指针回溯的。
- **你的任务**：在 `dsaac::kmpMatch` 中实现完整的 KMP 模式匹配算法（可直接调用 `dsaac::getNext` 函数）。
- **测试**：用 Step 1 中极端的测试用例来运行你的 KMP 算法，直观体会它在最坏情况下的性能优势。

### Step 3. KMP 算法的深度优化 (nextval)
- 原始的 `next` 数组在某些特殊情况下（如模式串为 `"aaaaab"` 时）依然会发生多余的内部字符比较。
- **你的任务**：实现更优化的 `getNextVal`（求解 `nextval` 数组）算法，并结合它来运行极速版的 KMP 匹配。
- **对比**：自己设计具有多重复片段的测试样例，打印并分析 `next` 数组与 `nextval` 数组的区别，以及有没有带来实际的常数级性能改善。

## 行为要求

- 涉及到长度的返回值/传参请妥善处理，推荐强制转型保证安全退出或使用 `std::size_t` 或 `int` 规范处理，避免无符号数导致的越界。
- 匹配成功应返回主串中初次匹配成功所在的首字母索引，失败应返回 `-1`。
